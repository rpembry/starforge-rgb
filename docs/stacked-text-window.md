# Stacked text window (issue #9 slice)

This is an opt-in, foreground GTK4 regular application window for the existing coordinator. The coordinator remains the only owner of source events, priority, cancellation, policy and expiry. `text_snapshot()` reads at most 32 detailed active leases in priority/recency order and returns no entries while the text channel is quiet, muted or in DND. It also reports total live cues, bounded per-source counts, and an identity/revision index for all active leases (at most the coordinator's 4096-lease cap). The index gives the view authoritative cancellation/expiry evidence even when a dismissed cue falls outside the 32 detailed entries; that cue does not reappear or duplicate history merely because higher-priority cues temporarily truncate it. The view distinguishes groups beyond its eight visible rows from cues omitted by the 32-entry detail cap. The window groups only events with an explicit source/group value. Each row includes source, UTC time, severity, status and provenance confidence; optional text is displayed only when supplied. Sound-only events have a source/time row with no invented body. Nonprinting event-body characters are replaced in the view so directional controls cannot reorder source labels.

The model supports dismissing indicators without cancelling their RGB/audio cue, expiry cleanup, keyboard navigation through the GTK list, Delete/Backspace dismissal, a visible dismissal button, and screen-reader labels. Dismissal and metadata history follow each accepted lease revision: a new failed or critical update for a previously dismissed subject appears, while duplicate refreshes stay dismissed. It keeps at most 50 in-memory metadata history records for at most one hour of injected monotonic elapsed time, with no message bodies by default. Wall time is used only for displayed event time. A clear button purges history. Source exclusions apply to indicators and history; replacing exclusions immediately purges newly excluded history. Lock status is read from GNOME's read-only ScreenSaver `GetActive` call; a missing or failed lock check hides both indicators and history. Quiet/DND also hides both. No content or setting is written to disk.

The explicit `--synthetic-preview` mode opens only built-in synthetic cues and no socket or host settings. The explicit `--serve --socket PATH --config PATH` mode reads the protected host configuration and starts the existing restricted Unix socket receiver for this foreground window. If settings are missing or invalid, the inherited safe baseline remains manually quiet. The app does not install a service, change desktop settings, call GNOME's notification `Notify` method, or install a shell extension. Wayland global overlay placement is not claimed.

The text projection sink accepts a primary plan into the local view adapter; `accepted` never means the user saw it. Lower-priority leases can still appear in the stack even when their transient channel result is `preempted`, and a cue with no body can still have a metadata row while its text-body channel result is `absent`. These are presentation projections of coordinator state, not a second output arbiter. Real visible, keyboard, screen-reader, lock-transition and screen-bounds acceptance checks have not been run. The initial supported route is a regular GNOME/Wayland window; Windows/macOS adapters and an optional overlay remain separate work.

# One foreground printer completion, text only

`python -m starforge_cues.text_window --printer-text` is a separate, opt-in GTK4 session. It uses the reviewed subscribe-only printer collector, host-owned account setting, bound Unix listener, one existing coordinator and **only** a text projection sink. It constructs no audio or RGB sink, starts no service and sends no printer command. The window starts observing when presented and stops its owned listener and client when closed. It can wait for a real proven `RUNNING` → `FINISH` report without a fixed 120-second test window; closing it ends the session.

Required arguments are `--config` (existing private host quiet policy), `--ingress-config` (private allowed account and runtime root), `--printer-host`, `--printer-serial`, `--printer-ca-file`, and `--printer-peer-sha256`. `--printer-credential-file` selects an existing private access-code file; otherwise the collector's existing private default is used. `--bambu-legacy-ca` is available only when its separately verified compatibility mode is appropriate. Audio arguments are refused. Do not put the access code on a command line or in Git. Exact printer values belong in the user's existing protected local launch route, not this public document.

The host policy governs manual quiet, DND, muted text and quiet windows. A missing or invalid host policy stays quiet. The window additionally hides text while GNOME's screen lock is active or notification banners are disabled; failure to read either status hides content. The printer collector does **not** start unless a loaded policy currently permits text and the window can display it. If that visibility condition becomes false while observing, the session stops instead of silently waiting through an unobservable completion; a transition during the shutdown race remains unconfirmed. A proven completion or failure has a 30-second coordinator lease, but its fixed generic text card remains in this foreground window until Dismiss or Close so the user can read it. The card is hidden during quiet or lock and may appear after visibility returns; no receipt claims the user saw it. The window shows a generic last explicit printer state while observing, without job IDs, serial, access code or report contents. If shutdown cannot confirm the collector stopped, the command exits with a failure result instead of reporting normal cleanup.

Fake verification uses `PYTHONPATH=src python -m unittest tests/test_printer_text_host.py -v`. It checks one completion through temporary UDS and fake text, the held card, source exclusion, hidden-state removal and owned-session cleanup. Passing source tests do not prove a printer completion, window visibility or user perception. A publisher failure after terminal detection may lose the event; there is no durable queue or automatic retry. The first live text test needs the exact reviewed build and a user-confirmed visible card. Audio and RGB are separate later gates.

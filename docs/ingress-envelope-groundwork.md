# Ingress and protocol data groundwork (#53, #63)

`ingress_contract` defines host-owned `IngressBinding`, strict proposed `publish` / `retract` / `hello` frame values, and an authorization check that carries the binding ID forward. Binding scope limits source IDs, statuses, severity, confidence, text, subjects and retraction. The pure frame parser accepts a mapping with `proto: 1`; it does not change the existing bare-event Unix socket or authenticate its peer. A transport adapter must establish the binding from protected host configuration and local peer/listener context before these checks are a security boundary. No token is accepted from a producer frame.

`GenerationRef` and `GenerationIds` define a process epoch plus bounded monotonic ordinal distinct from reusable source/subject names. The host must create a fresh unpredictable 128-bit epoch at process start and allocate under the coordinator lock. `AdmittedTransition` carries generation, revision, event ID and semantic status for exact matching before future audio dispatch. These types are not yet wired into `LeaseBook`, the selector or the socket; the current producer v1 event and receipts remain unchanged.

The proposed envelope is strict within its version. A `retract` request carries only source, subject and request ID, then must be checked against the caller binding and currently owned generation. A `hello` response should expose only that binding's allowed capabilities. The current `status: cancelled` v1 event remains a compatibility path until #63 defines version dispatch and migration tests. Byte limits, duplicate JSON-key rejection, local peer checks, replay budgets, status cursor authentication and a mandatory host registry are future integration gates, not properties of this pure mapping parser. No service or producer is activated here.
